# TypeORM

- **Repo**: https://github.com/typeorm/typeorm
- **Used by**: `@rapiq/adapter-typeorm` (peer dependency `typeorm@^0.3.28`)

`@rapiq/adapter-typeorm` adapts a parsed rapiq `Query` onto TypeORM's `SelectQueryBuilder` without a live database connection.

## Code Mappings

| TypeORM | rapiq | Notes |
|---------|-------|-------|
| `SelectQueryBuilder` (`src/query-builder/SelectQueryBuilder.ts`) | `TypeormAdapter` (`packages/adapter-typeorm/src/adapter/module.ts`) | Builder bound at construction (`{ queryBuilder: qb }`); `execute(query)` walks the query and applies the state in one call |
| `RelationMetadata.inverseEntityMetadata` (`src/metadata/RelationMetadata.ts`) | `RelationsAdapter.join()` (`packages/adapter-typeorm/src/adapter/relations.ts`) | Metadata of the entity **targeted** by a relation — used to walk nested relation paths. `entityMetadata` is the *owning* entity (using it silently drops nested paths whose segment doesn't also exist on the root entity). |
| `connection.options.type` (`src/data-source/DataSourceOptions.ts`) | `resolveQueryDialect()` (`packages/adapter-typeorm/src/dialect.ts`) → `resolveDialect()` (`packages/adapter-sql/src/dialect/resolve.ts`) | Connection type name → `DialectOptions` preset; postgres preset is the last-resort fallback. |
| `DataSource.buildMetadatas()` (`src/data-source/DataSource.ts`, protected) | `createUnconnectedDataSource()` (`packages/adapter-typeorm/test/data/factory.ts`) | Builds entity metadata without opening a connection — enables dialect specs (incl. `mysql`, needs `mysql2` devDep for driver construction) with no live database. |
| `SelectQueryBuilder.expressionMap.joinAttributes` | `RelationsAdapter.join()` dedup | Pre-existing joins are matched by `joinAttribute.alias.name`; matching joins are skipped (idempotency). |
| `SelectQueryBuilder.andWhere()` + `createWhereExpression()` (`src/query-builder/SelectQueryBuilder.ts`, verified on 0.3.30) | `FiltersAdapter.execute()` (`packages/adapter-typeorm/src/adapter/filters.ts`) | `andWhere()` records an `and` clause without clearing `expressionMap.wheres`. During rendering, the first condition is emitted as `WHERE ...` regardless of its stored conjunction; later conditions receive `AND`. The adapter therefore guards empty SQL and uses `andWhere(sql, params)`: a caller-owned tenant/auth predicate is preserved, while a filter on an otherwise empty builder still produces valid SQL. A TypeormAdapter/builder pair remains per-request; re-running onto an already-mutated builder is not a rollback operation. |
| `EntityMetadata.findRelationWithPropertyPath()` / `findColumnWithPropertyPath()` (`src/metadata/EntityMetadata.ts`, verified on 1.1.0) | `RelationsAdapter.isRelationPath()` + `findColumnByPropertyPath()` (`packages/adapter-typeorm/src/adapter/{relations,filters}.ts`) | Embedded column paths (`@Column(() => Profile)` → `profile.firstName`) are dotted but **not** relations: `findRelationWithPropertyPath('profile')` returns `undefined` while `findColumnWithPropertyPath('profile.firstName')` resolves the full remaining path to the embedded column. `isRelationPath` walks relation metadata per segment so `@rapiq/adapter-sql`'s `parseField` keeps embedded remainders on the parent alias instead of deriving a join (#779). |
| `DefaultNamingStrategy.columnName()` (`src/naming-strategy/DefaultNamingStrategy.ts`, verified on 1.1.0) | asserted via metadata in `packages/adapter-typeorm/test/unit/embedded.spec.ts` | Embedded column database names camelCase the prefixed path with only the first letter after each boundary uppercased: `profile` + `firstName` → `profileFirstname` (not `profileFirstName`). Tests read `findColumnWithPropertyPath(...).databaseName` instead of hardcoding. |
| `SelectQueryBuilder.select()` / `orderBy()` (`src/query-builder/SelectQueryBuilder.ts`, verified on 1.1.0) | `FieldsAdapter` / `SortsAdapter` (`packages/adapter-typeorm/src/adapter/{fields,sort}.ts`) | Both resolve `alias.propertyPath` keys through entity metadata **including embedded paths** (`user.profile.firstName` → `"user"."profileFirstname"`), so the typeorm fields/sort adapters pass property paths unescaped; only raw WHERE fragments need the database-name resolution (`resolveFieldName`). |

| `DateUtils.mixedDateToUtcDatetimeString()` / `mixedDateToDateString()` (`src/util/DateUtils.ts`, exported from the package root, verified on 1.1.1) | `FiltersAdapter.bindValue()` (`packages/adapter-typeorm/src/adapter/filters.ts`) | The same formatters every driver's `preparePersistentValue` writes with, so a filter operand is spelled exactly like the stored value. `mixedDateToUtcDatetimeString` yields `'YYYY-MM-DD HH:mm:ss.sss'` in UTC; `mixedDateToDateString(value, { utc })` yields `'YYYY-MM-DD'` and takes the column's own `utc` option (`ColumnMetadata.utc`). |
| `Driver.preparePersistentValue()` (`src/driver/*/`, verified on 1.1.1) | deliberately **not** used by `bindValue()` | Two blockers: it applies `columnMetadata.transformer` (the entity-side write direction, not a wire value), and on pg/mysql a `datetime`/`timestamp` returns `DateUtils.mixedDateToDate()`, i.e. a `Date` object. node-postgres serializes a `Date` with the HOST's local offset and `timestamp without time zone` discards that offset, so the window shifts on a non-UTC host (issue #939). Only `AbstractSqliteDriver` writes the UTC string form directly. **Measured 2026-09-22** against postgres 16 in docker from a UTC+2 host: a row seeded through `repository.save()` stores the LOCAL wall clock, so a UTC-bound equality misses it by the host offset. `date.db.spec.ts` therefore seeds the storage literal through a raw `set({ col: () => ':param' })` update, which keeps the spec measuring rapiq's contract (a zone-less column means UTC) instead of typeorm's write-path zone. The spec is a `.db.spec.ts` so CI's `tests-db` matrix replays it on mysql and postgres; all three dialects pass. |
| `ColumnMetadata` (`src/metadata/ColumnMetadata.ts`) | `FiltersAdapter.resolveColumn()` | Not exported from typeorm's package root (unlike `EntityMetadata`/`ColumnType`), so the adapter keeps the type inferred from `findColumnByPropertyPath` rather than importing it. |
