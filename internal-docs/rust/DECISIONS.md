# Decision log: Rust core and bindings

Dated record of what was decided, by whom, and what was rejected, so later
work does not re-litigate it. Newest entries last. Status is one of
**settled** (maintainer decision), **adopted** (forced by evidence or
implementation, not contested), **proposed** (recommended, awaiting a
decision) or **open**.

Concepts and the package structure these decisions produce are described in
[ARCHITECTURE.md](ARCHITECTURE.md); the phases that implement them in
[MIGRATION.md](MIGRATION.md); measurements in [SPIKE.md](SPIKE.md).

## Settled and adopted

### R1. One Rust implementation, TS packages built on it (settled, 2026-10-08)

The TypeScript packages stop carrying their own parser, schema-resolution,
filter-semantics, codec, SQL-rendering and evaluation logic and call Rust.
Only adapters that exist to drive a TypeScript library keep their own code:
`@rapiq/adapter-typeorm`, `@rapiq/adapter-prisma`, `@rapiq/adapter-drizzle`.

Context: the spike showed the semantics port cleanly but bring no speed gain
to JS users; the motivation is one implementation across languages.

### R2. Runtime: napi on Node, WASM fallback elsewhere (settled, 2026-10-08)

Native addon on Node; WASM in browsers, on unsupported platforms and in edge
runtimes. Rejected: WASM only (slower calls), napi only (would drop browser
support for `defineQuery` and the URL codec's encode).

### R3. Migration order (settled, 2026-10-08)

Plan first, then phase by phase; each phase deletes the TS implementation it
replaces, and ships only when every affected package's existing test suite
passes unchanged on Rust.

### R4. Coarse JSON boundary (adopted, 2026-10-08)

Bindings exchange JSON strings, one call per parse, merge, plan or render;
never one call per AST node. Evidence: the spike (napi call overhead about
2 µs, IR serialization dominated until serialized directly).

### R5. Layout: `packages/<package>/<ecosystem>` (settled, 2026-10-09)

First level is the rapiq package, second level the ecosystem: `node` (npm,
TypeScript), `rust` (crate), `python` (PyPI), later `jvm`. The `packages/`
container stays. `packages/docs` keeps no ecosystem level (an app, not a
library). Shared fixtures live in `conformance/`, design notes in
`internal-docs/`.

Rejected: package directories at the repository root (about 13 top-level
directories); everything under `crates/` (signals Rust-only); rolldown's
split into separate `crates/` and `packages/` trees (scatters one package
over two places).

### R6. Directory names without prefix, published names with it (settled, 2026-10-09)

Directories are named by role (`core`, `node`, `python`), never `rapiq-core`.
Published names keep the prefix because crates.io and PyPI have no
namespaces: crates `rapiq-<package>`, distributions `rapiq-<package>`.

### R7. Bindings per package (settled, 2026-10-09)

Every Rust-backed rapiq package owns its native addon; there is no shared
binding package. The napi crate lives inside the npm package at
`packages/<package>/node/binding` (crate `rapiq-<package>-node`,
`publish = false`); the PyO3 crate at `packages/<package>/python` (crate
`rapiq-<package>-py`, `publish = false`).

Consequence (accepted): each addon links its own copy of `rapiq-core`, so
binaries are larger, and nothing crosses between packages but the JSON IR;
a native handle (compiled schema, predicate) belongs to the addon that
created it. Rejected: rolldown's single binding crate (one addon for the
whole project).

### R8. Per-platform npm packages, generated (settled, 2026-10-09)

Each addon ships as optional dependencies `@rapiq/<package>-<platform>` (plus
`@rapiq/<package>-wasm32-wasi`), of which npm installs only the matching one.
They are generated by `@napi-rs/cli` at publish time; `npm/` is gitignored.
Rejected: one tarball carrying every platform's binary.

### R9. Python src layout (adopted, 2026-10-09)

The Python package lives in `src/<module>/` next to the Rust `src/lib.rs`
(`python-source = "src"`). Forced by evidence: with the package at the
project root, `python -m pytest` imported the source folder instead of the
installed wheel.

### R10. One umbrella package per language (settled, 2026-10-09)

Each ecosystem gets an umbrella that bundles the parts, at
`packages/rapiq/<ecosystem>`, using that ecosystem's idiomatic selection
mechanism:

| Ecosystem | Umbrella | Selecting parts |
|-----------|----------|-----------------|
| Rust | crate `rapiq`, re-exporting the part crates | Cargo features (`features = ["parser-mongo"]`), only selected parts compile |
| Python | distribution `rapiq`, dependencies only, no code | extras (`pip install rapiq[mongo,url]`) or installing parts directly |
| npm | package `rapiq` (name and version: D7) | the scoped `@rapiq/*` packages are the selection; the umbrella installs everything |

Replaces an earlier proposal (a single Python module linking every crate),
rejected because Python users should be able to install only the parts they
need, e.g. not every parser.

### R11. Python parts are separate distributions (settled, 2026-10-09)

Each Rust-backed package publishes its own wheel: `rapiq-core`,
`rapiq-parser-mongo`, ... Imports share the `rapiq.` prefix through a
namespace package (`rapiq.core`, `rapiq.parser_mongo`), which requires the
umbrella distribution to ship no `rapiq/__init__.py`. Same cross-package
consequence as R7: Rust objects cross between wheels only as JSON (a part may
cache by content). Rejected: a shared native library loaded by several
wheels, or C-level APIs between extension modules (fragile in Python
packaging).

Implemented 2026-10-09: `packages/core/python` publishes as `rapiq-core`,
imported as `rapiq.core`; the umbrella `packages/rapiq/python` is the
distribution `rapiq`.

### R12. Releases via trusted publishing (adopted, 2026-10-09)

crates.io and PyPI publish from GitHub Actions through OIDC trusted
publishing, without stored tokens (`.github/workflows/rust-release.yml`,
manual until phase 0 moves it into the release-please flow).

### R13. Host value references (adopted, 2026-10-09)

Values JSON cannot carry faithfully (JavaScript `Date`, `RegExp`, `bigint`,
`NaN`, `-0`, objects) cross the boundary as descriptors
`{"$rapiq.ref": n, type, text, truthy, number?, source?, flags?, operator?}`
holding exactly the facts the lowering reads (string conversion,
truthiness, finite number, regex source/flags, a detached condition's
operator). Rust echoes them untouched into its output and the host swaps
the originals back in (`IRValueTable`). The table has two modes: `plain`
(transport: plain objects stay JSON, `-0` becomes `0`) and `reference`
(the in-process binding path: every object by reference, so identity and
nested values survive). Forced by evidence: date operands are a
documented feature, and `JSON.stringify` throws on `bigint`.

### R14. Envelope for internal binding calls (adopted, 2026-10-09)

Functions `@rapiq/core` calls internally return
`{"ok":true,"value":...}` or `{"ok":false,"error":{code,message,subject}}`
instead of throwing, so the TypeScript side rebuilds the exact typed error
through the same factory (`AdapterError.featureUnsupported(feature)` sets
`feature`), which a napi exception (code and message only) cannot carry.

## Proposed (phase 0, from the rolldown and node-rs reviews)

Details and sources: [.agents/references/rolldown.md](../../.agents/references/rolldown.md),
[.agents/references/node-rs.md](../../.agents/references/node-rs.md).

Status 2026-10-09: P1, P2, P3, P4, P6 and P7 are adopted for `core`
(see the notes on P2 and P3); P5 is pending.

- **P1. `napi` block in each npm package's `package.json`** (binary name,
  package name `@rapiq/<package>`, targets), driving `napi build`,
  `create-npm-dirs`, `artifacts` and `prepublish`.
- **P2. Commit the generated loader and type declarations.** napi's generated
  `index.d.ts` gives the TS wrappers exact types from the Rust signatures and
  lets TS contributors type-check without cargo. Generate the ESM loader
  variant (rapiq packages are ESM-only), and keep the loader's check that the
  installed platform package's version matches (rolldown does this).
  *Refined when adopted*: the CommonJS loader (`binding/index.cjs`, as
  rolldown commits) is required lazily through `createRequire` on the first
  call that needs Rust, which keeps `import '@rapiq/core'` free of native
  loading and keeps `node:module` out of the browser entry. The loader bakes
  in the package version, so the release flow regenerates it.
- **P3. Public API as a factory over a binding**, with `src/index.ts` (native
  binding) and `src/browser.ts` (WASM package) selected by an `exports`
  `browser` condition (node-rs bcrypt pattern). Feeds D2.
  *Adopted at the binding seam*: `src/module.ts` is the shared API,
  `src/index.ts` (Node) registers the napi loader, `src/browser.ts`
  (`browser` condition) gets the WASM binding; `setBinding()` lets a host
  supply one. A call without a binding fails typed
  (`AdapterError.bindingUnavailable`, `ErrorCode.BINDING_UNAVAILABLE`).
- **P4. A shared binding-support crate** (`packages/binding-support/rust`):
  mimalloc global allocator (the spike measured the evaluator at 139 ms to
  77 ms with it), the JSON boundary helpers and error conversion, used by
  every per-package binding.
- **P5. CI by target, not by package**: one build job per target building
  every package, uploading `bindings-<target>`; tests per platform (Docker for
  musl and ARM, Node 22 and 24, WASI); one publish job assembling artifacts.
- **P6. Workspace hygiene**: `rust-toolchain.toml`, `[workspace.dependencies]`,
  `[workspace.lints]`, `strip = "symbols"` in the release profile.
- **P7. Fixtures per package** (`packages/<package>/fixtures/`), with
  `conformance/` keeping only the shared runner.

## Open

Detailed in [MIGRATION.md](MIGRATION.md#decisions-needed): D1 hooks
protocol, D2 WASM in the browser (incl. napi `wasm32-wasip1-threads` versus
wasm-bindgen), D3 `adapter-sql` extension surface, D4 `adapter-memory`
performance, D5 error messages from Rust, D6 version coupling, D7 npm
umbrella name.

Decided 2026-10-09 (maintainer): **D5** error messages come from Rust
verbatim (pinned byte for byte by the plan fixtures); **D6** npm platform
packages, crates and Python distributions version in lockstep with the TS
packages; **D2** both WASM variants: napi `wasm32-wasip1` (no threads,
deferred loader) ships now as the browser binding and the Node fallback,
and the wasm-bindgen crate is kept building in CI so the browser payload
can be re-measured as more Rust is exposed (measured: ~184 KB versus
~76 KB gzip; napi's threaded variant fails on non-isolated pages). D7: no
npm umbrella is created until decided. Open: D1, D3, D4, D7.
